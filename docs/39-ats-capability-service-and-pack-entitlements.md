# ATS 服务、能力包权益与多模型来源方案

## 1. 目标与边界

LWB 是基于官方 DSH 桌面端能力构建的产品层。桌面端和 Web 端继续使用同一套能力包、页面、模块和业务逻辑，差异只在宿主形态。官方 DSH 负责官方账号、模型设置和基础运行时；LWB 负责能力包注册、动态加载卸载、能力包工作区以及 LWB 自己的商业服务接入。

本方案解决四个问题：

1. LWB 账号、积分、会员和商业权益如何接入现有 ATS。
2. 能力包如何声明服务依赖、支持的模型来源和权益信息。
3. 公开口播视频能力包如何同时保留官方模型、ATS 模型和用户自定义模型。
4. 公共代码与商业代码如何划分，避免维护两份相同的 LWB 或口播能力包。

本阶段只固化契约和边界，不改变口播视频现有页面、接口、任务状态机和百炼 API Key 配置路径。

## 2. 仓库职责

| 仓库 | 负责内容 | 发布方式 |
| --- | --- | --- |
| 公开 LWB 仓库 | DSH Profile 适配、桌面端、Pack SDK、能力包注册/加载/卸载、公开能力包、Provider 路由接口 | MIT 或新的非商用开源协议，按版本发布 |
| `ai-transfer-station` | 账号、登录、Token、积分、会员套餐、订单支付、权益校验、云端异步任务、上游供应商密钥 | 私有服务，独立部署 |
| 私有商业能力包仓库（可选） | 不希望公开源码的高级能力包和商业工作流 | 私有包源、授权下载或随商业版本分发 |

不新增一份完整的“商业版 LWB 桌面端”源码。公共功能和公开口播能力包只在公开仓库维护；商业版本通过依赖版本更新、ATS 权益校验和独立私有能力包获得差异。

## 3. 运行时分层

```text
官方 DSH
  ├─ 官方账号、官方模型、系统设置
  └─ Loader、Agent、客户端模块图

LWB 公共层
  ├─ Pack SDK 与 manifest
  ├─ 能力包注册、动态加载卸载、专属工作区
  ├─ 多 Provider 路由边界
  └─ LWB 账号/ATS 客户端（后续阶段）

ATS 私有服务
  ├─ LWB 账号与 Token
  ├─ 会员、积分、订单和权益
  ├─ TTS、字幕、封面等云端任务
  └─ 上游百炼等供应商密钥
```

官方 DSH 账号与 LWB 账号保持独立。启动 LWB 不应强制用户登录 ATS；未登录用户仍可使用不需要 ATS 的公开能力包和 BYOK 路径。

## 4. 能力包服务契约

从 Pack manifest schema v1 开始，能力包可以声明以下可选字段：

```json
{
  "minHostVersion": "0.1.0",
  "requiredServices": ["tts", "subtitle", "cover-image"],
  "providers": ["official", "ats", "custom"],
  "entitlements": ["pack.spoken-video"]
}
```

- `minHostVersion`：能力包要求的最低 LWB Host 版本。未声明时不增加版本限制。
- `requiredServices`：能力包需要的逻辑服务标识。它描述能力依赖，不代表当前一定使用云端服务。
- `providers`：能力包支持的模型/服务来源，固定为 `official`、`ats`、`custom` 三类。它是能力声明，不是权限授予。
- `entitlements`：可选的 ATS 权益标识，用于市场展示和服务端授权提示。它不是本地安全边界。

所有字段都只允许声明式、浏览器安全的数据。Host 会校验、规范化并冻结 manifest，再将同样的元数据投影给注册表和市场页面。旧能力包不声明新字段时，行为和返回结构保持兼容。

## 5. 口播视频能力包的 Provider 规则

口播视频继续保留当前 `bailian`、`scitiger`、`legacy` 的内部兼容标识和现有配置界面。新的产品层 Provider 语义映射如下：

| 产品层来源 | 典型实现 | 登录/配置要求 |
| --- | --- | --- |
| `official` | DSH 官方模型与官方设置 | 使用官方 DSH 登录和模型配置 |
| `ats` | LWB Host 调用 ATS 云端任务 | 登录 LWB 账号并消耗积分/会员权益 |
| `custom` | 用户自己的百炼或兼容服务 URL、模型和 API Key | 用户自行配置，继续支持 BYOK |

因此，用户拿到公开版本后仍可以只配置自己的百炼 API Key 使用公开能力包；ATS 是新增的默认服务来源，不替换 BYOK，也不把百炼 API Key 下发到 ATS。

ATS 服务端必须再次校验账号、会员、积分、能力包和具体服务权限。客户端隐藏菜单或能力包卡片只能改善体验，不能作为授权边界。

## 6. ATS 接入原则

后续实现采用 Host 统一入口：能力包只拿到当前包的 Host 服务作用域，不直接读取 ATS Token、不直接保存供应商密钥，也不绕过 Host 调用任意远程地址。

Host 负责：

- LWB Token 的安全保存、刷新和注销；
- 当前账号、会员、积分和能力包可见性状态；
- 以能力包和服务标识发起 ATS 请求；
- 任务取消、超时、重试和错误映射；
- 在卸载能力包时取消未完成的本地任务。

ATS 负责：

- 账号身份和服务端会话；
- 积分冻结、成功结算、失败释放；
- 会员套餐和能力包权益；
- 上游供应商密钥和实际云端调用。

## 7. 分阶段实施

### 阶段一：契约固化（当前阶段）

- 扩展 Pack SDK manifest 校验和冻结逻辑。
- 将服务依赖、Provider、权益和最低 Host 版本投影到 registry/market。
- 为公开口播包声明 `tts`、`subtitle`、`cover-image` 依赖以及三类 Provider。
- 增加契约测试和文档。

### 阶段二：Host 账号与服务入口

- 增加 LWB 设置中的账号登录、注册、退出和 Token 刷新。
- 增加 Host-owned ATS client 和凭据存储，不改变官方 DSH 登录。
- 增加账号、会员、积分和权益的只读状态接口。

### 阶段三：能力包目录与权益

- 市场根据 ATS 返回的可见能力包过滤展示。
- 加载商业能力包前由 ATS 和 Host 双重校验。
- 未登录、无权益、积分不足分别返回可操作的状态，不影响 BYOK 能力。

### 阶段四：服务路由

- 将口播包的配音、字幕、封面服务接入统一 Provider 选择。
- `ats` 路径调用 ATS 异步任务并同步本地任务状态；`custom` 路径沿用现有用户配置；`official` 路径沿用 DSH。
- 保持现有模块页面和业务流程不变，只替换服务实现边界。

### 阶段五：商业能力包分发

- 私有能力包独立版本化和授权分发。
- 公共 LWB 通过 Pack SDK 和 Host 扩展接口加载私有包。
- 公共能力包修复只改公开仓库，商业产品升级对应公开依赖版本，不复制源码。

## 8. 版本、兼容与安全规则

- DSH 上游版本、LWB Host 版本、Pack SDK schema 版本和能力包版本分别管理。
- manifest 新字段全部可选；字段校验失败时拒绝挂载，避免半可用能力包。
- 能力包不得在 manifest 中声明 URL、Token、API Key 或可执行路径。
- 权益字段只用于目录和授权协商，最终权限以 ATS 服务端结果为准。
- 公开源码被用户自行编译运行属于公开发行范围，不能依靠 UI 隐藏保护商业能力。
- 修改公共功能时只改公开仓库；只有商业专属能力包或 ATS 服务逻辑才在私有仓库修改。

## 9. 当前阶段验收标准

1. 旧 manifest 测试全部通过，未声明新字段的能力包输出不变。
2. 新 manifest 能正确声明并冻结服务依赖、Provider、权益和最低 Host 版本。
3. registry 和 market 返回这些声明，但不暴露凭据或内部服务地址。
4. 口播视频现有页面、Provider 配置和百炼 API Key 路径没有改动。
5. `npm test` 和 Pack SDK/registry 定向测试通过。
