# 41 能力包内的会话与官方右栏

实施日期：2026-09-30。适用 DSH `0.2.0-rc.2`。本文记录"能力包页面如何展示自己的会话与产物"，以及被否掉的替代路线。

## 问题

场景能力包页面渲染在 `shell.overlay` 里：一个不透明的整页，覆盖官方 frame 的 `main` 与 `rightbar` 两列。于是包页面既看不到官方对话区，也看不到官方右栏——而右栏不只是"看产物"：文档预览（全部类型）、文件、终端、浏览器、改动评审、第三方插件注册的 tab 类型、快捷键、开合/全屏都在里面。

自己把右栏或产物预览重画一遍，等于在官方 shell 旁边搭第二套外壳：**官方升级只会升级它自己那套，自绘的那套永远要人肉追**。因此本方案的原则是：**不复制任何官方内容，只让官方那一份对包会话生效。**

## 决策：包页面渲染官方对话，焦点卡片决定官方右栏跟随谁

| 组成 | 做法 |
|---|---|
| 每个模型的对话区 | 宿主下发 `renderConversation({ sessionId })`，内部用官方 `conversation.content` Factory + 该会话自己的 `SessionProvider` 作用域。回答、工具调用、文件 chip、输入框（可继续对话）都是官方原件 |
| 官方右栏 | **不重画**。包页面把"正在操作的卡片"告诉宿主（`focusSession(sessionId)`），宿主把 frame 的当前会话指向该会话，官方右栏（frame 的第三列）随即对这条会话生效 |
| 让位 | 包页面所在的 overlay 从右边缘让出右栏列宽：宿主测量**当前显示的那个**官方面板元素（`[data-sidebar-right-panel]` 中不被 `[hidden]` 视图遮住的那一个，读它的 `data-sidebar-right-open` / `data-sidebar-right-panel` / 宽度），写入 `--lwb-rightbar-inset`；`.lwb-overlay` 用 `inset: 0 var(--lwb-rightbar-inset,0px) 0 var(--lwb-sidebar-width)` 让位。收起、全屏、窄屏都不让位（全屏面板本来就盖住页面） |
| 文件 chip | 嵌入对话里的 chip 仍调用官方 `sidebarRight.openResource`。宿主拦截后**先聚焦该会话**，再等官方已挂载的 seat 发布（`sidebarRight.mounted`）后原样调用官方逻辑，于是文件在官方预览里打开。属于包会话之外的地址一律原样透传 |
| 面板唯一性 | 开过 tab 的会话会把**自己的**面板留在 DOM 里（随视图 `hidden`），所以"当前的 panel"必须按可见性挑，否则会把隐藏的那个当成列宽与展开状态 |

自绘的只有：卡片外壳（模型名/状态）、运行记录（运行结束时落库的产物清单）与左栏。**会话内容、产物查看、右栏的每一项功能都不由我们实现。**

## 展开入口：嵌入会话的头部条

官方的"展开右侧栏"按钮注册在槽位 `conversation.session.header.corner` 上，而那个会话头部属于 **frame 的主面板链**：

```text
main → main.conversation → conversation.header → conversation.session.header → …header.corner（ExpandButton）
```

包页面嵌入的是 `conversation.content` Factory（消息列表 + 输入框），链路上低于头部，因此**嵌入会话没有头部，也就没有那个按钮**。纯文本回答没有文件 chip 时，用户会看到"右栏能开但没有入口"。

宿主因此在嵌入外壳里补一条 28px 的头部条（**属于我们的 chrome，官方没有任何一部分被重画**）：

| 部分 | 来源 |
|---|---|
| 会话标题 | 官方会话列表快照 `sessions.list.byId[sessionId].displayTitle` |
| 展开/收起按钮 | 状态读**官方座位自己渲染的面板标记**（`[data-sidebar-right-panel][data-sidebar-right-open]`）+ `mounted`：服务只发布"当前会话"，不发布各会话的 layout，把 panel 标记当作可观察事实才与列里真正显示的一致；动作调官方 `toggleExpanded()`（内部作用于**已挂载的座位**，即聚焦卡片那条会话）；按钮上带官方快捷键提示 |

按钮带 `data-lwb-session-control` 标记，包卡片的捕获事件遇到该标记只更新卡片高亮，不提前导航。点击时由按钮先聚焦该卡片、等官方座位发布该会话，再通过官方动作设置用户要求的展开/收起状态，避免恢复会话旧状态后把「展开」变成「收起」。键盘触发同样有效。收起/展开的列宽变化由前面的 `--lwb-rightbar-inset` 让位机制处理。

### 面板的可见性规则：一个页面一份面板

官方 store 按**会话**记住右栏是否展开（这正是对话模块的行为：每条会话各记各的）。但测评页是同屏多张卡片共用一个 frame，按会话记忆会表现为"切回某张卡片时它上次的面板又自己打开了"。因此本页把面板当作**一个界面状态**，规则如下：

| 手势 | 面板 |
|---|---|
| 点某张卡片（或首次自动聚焦） | 目标卡片即使此前或从存储里带着展开态，也会收起（点卡片永远只会看到收起状态）。这次收起**等到手势结束**才开始：同一次手势里的官方控件可能带着一次"打开"，由它决定面板 |
| 点某张卡片头部条的「右侧栏」/「收起右栏」 | 聚焦目标卡片后，通过官方动作设置按钮要求的展开/收起状态；不反转刚恢复的旧状态 |
| 点卡片内的官方控件（文件 chip、产物卡片、改动、终端/文件/浏览器等） | 官方控件自己决定打开什么，且**这次打开就是结果**：跨卡片点产物时，frame 先切到该卡片，随后官方打开把该会话的面板展开并显示这个文件——首次点击即可见，不需要再点第二次 |
| 离开测评页（最后一个嵌入会话卸载） | 收起当前面板，再恢复进入前的会话，避免下次进入又"自己打开" |

只用到官方公开面：`mounted`（已挂载座位）、`openResource`、`isExpanded()`、`toggleExpanded()`，以及官方座位自己渲染的面板标记 `[data-sidebar-right-panel][data-sidebar-right-open]`；**不读不写官方 store**。两处等待都有上限、超时一律**放弃**，绝不把动作落到上一个会话上（否则文件会开进用户自己的对话右栏）：

- **官方打开**：官方要求"该会话的座位已挂载"**且**"该会话的面板表面已 mint"（其拒绝信息 `no session surface is mounted` 就是表面还没建好的观测），而 `mounted` 先于座位的那次渲染发布，所以第一次调用可能被拒绝——按这条信息重试若干帧；其它拒绝照原样抛出，交给对话模块的文件弹窗报告。打开成功后若面板仍未展开（官方只在新建 tab 时展开），补一次官方切换，保证"打开必然可见"。
- **切卡片收起**：等官方座位发布目标会话后再收起。

### 一个会话一份输入框：只挂载卡片中的 Conversation

官方**一个会话只有一份输入框**：输入状态机（`SessionInputShell`）按会话一份，并持有该会话唯一的 Lexical 编辑器；输入框组件把这个编辑器绑到自己的 `contenteditable` 节点上（`editor.setRootElement(el)`），而 Lexical 只认一个 root——换 root 时会把旧 root 的内容清空，旧节点上的 `contenteditable` 与 `data-lexical-editor` 却都留着。官方自己的用法天然满足这条前提：`variant: 'embedded'` 唯一的官方消费者是**子会话**的右栏聊天，那时 frame 主区显示的是父会话，两份从不重叠。

包页面同时做两件事：把每个模型的对话渲染进卡片，又让 frame 指向那张卡片的会话。于是**同一个会话的对话在屏幕上挂载了两份**——一份是卡片（可见），一份是 frame 中央列（被不透明的 `.lwb-overlay` 盖住，但仍挂载）。先挂载的那份被后挂载的那份抢走编辑器 root，只剩一个仍然可输入的壳，表现为：

- 在卡片里敲的字进了壳的 DOM，没有进状态机；
- 占位文字由 `draft === ''` 决定，于是官方占位（`发消息或创建任务，/ 调用指令，@ 文件或对话`）继续画在打字上面；
- 发送键由 `empty`（`draft.trim() === ''`）决定，于是恒为禁用，Enter 也发不出去。

官方右栏把 `activePanelId === null` 且选中的会话当作在屏会话。将中央列切到另一个 `main` 面板会使右栏消失；但这不要求必须挂载完整的 frame Conversation。

2026-10-01 修订：撤销 `claimComposerSurface` 的 root 监听、重新绑定与焦点转移。它可能通过卡片 `onFocusCapture` 再次进入导航，不再作为编辑器归属方案。

| 组成 | 做法 |
|---|---|
| frame 内容 | 第一条嵌入会话挂载时，通过公开 slot 注册表为 `main.conversation` 注册优先级为 `-10` 的空占位；最后一条卸载时撤销该注册，恢复官方 Conversation |
| 官方右栏 | 保持 `activePanelId === null` 和官方会话选择，因此右栏仍为当前卡片提供官方文件、产物与终端；无需复制右栏或修改上游 |
| 卡片输入 | 每个 Session 只挂载卡片中的官方 composer，宿主不再调用 `editor.setRootElement` 或监听 editor root |
| 重复 focus | 从 `uiSession.adapter.current` 读取当前会话，同一会话的重复 focus 不再等待 `sidebarRight.mounted` 才能阻止重复导航 |
| 加载 | 每次卡片 retain 带独立取消信号，15 秒未 ready 显示超时与「重试」；卸载、失败与超时仅释放该卡片自己的引用，迟到结果不能覆盖新状态 |

代价与边界：

- 只替换被 overlay 覆盖的 Conversation 内容，不改变官方主面板选择，不操作官方编辑器。
- 会话恢复读取 `uiSession.adapter.current`，不依赖新版本已移除的 `sessions.list.current`；用户期间选择了其他会话时优先保留该选择。
- 历史流超时不等于数据损坏；任务原有的回答快照仍可通过「并排对比回答快照」查看。超时不会取消其他引用共享的历史打开过程。
- 依赖公开 slot 的优先级与卸载行为、`main.conversation` 入口、官方 UI 当前会话和右栏可见性规则，升级时必须验证。

## 生命周期与边界

- **进入**：任一嵌入对话挂载时进入"包会话模式"——记录进入前的当前会话、开始测量右栏列宽，并替换 frame 的 Conversation 内容。包页面首次拿到会话后自动聚焦第一个模型。
- **切换**：点某张卡片（`onPointerDownCapture` / `onFocusCapture`）即聚焦该会话；之后这张卡片里的官方展开按钮、文件 chip、右栏 tab 全部指向它。聚焦立刻切 frame，应收起的那个面板则等到手势结束（`pointerup` / `pointercancel` / `click`）再收——这样同一次手势里"打开产物"的那次官方调用先落地，成为结果。每个会话的右栏状态（打开的 tab、位置）由官方按会话持久化，切回去还是那个模型自己的右栏。
- **退出**：最后一个嵌入对话卸载时恢复进入前的会话。**只有当 frame 仍显示这次模式里的会话时才恢复**——用户期间的主动导航优先。
- **代价（必然，非实现选择）**：官方右栏一帧只有一份且跟随当前会话，因此同屏 4 张卡片共用一份右栏，跟随"正在操作的那张"；进入模式期间 frame 的当前会话是包会话（对话模块自己的会话因此暂时让位，退出即恢复）。若不允许这一步，就只剩自绘右栏那条追不上官方的路。
- 兼容性：右栏服务用 `ctx.get('sidebarRight')` 在使用时查找，缺失时只少一层路由，工作台照常启动。

## 数据：每次运行一个目录

同一题目并行跑多个模型时，多个会话共享一个工作目录会让产物无法归属、且互相可见。现在：

```text
pack-state/workspaces/model-review/
├── data/                                # 测评数据：题库、任务快照
└── runs/
    └── <taskId>/                        # 一次测评任务
        ├── <runId>/                     # 模型 A 的会话 cwd（官方右栏只显示这里的文件）
        ├── <runId>/                     # 模型 B
        └── ...
```

- 包通过 `sessions.create({ ..., cwd: 'runs/<taskId>/<runId>' })` 指定会话目录；宿主只接受包工作区内的 `/` 分隔相对路径，逐段创建并拒绝符号链接，越界报 `PACK_WORKSPACE_INVALID` / `PACK_WORKSPACE_UNSAFE`。
- 产物地址是 `dsh-resource://file/session/<runSessionId>/<path>`，官方按该会话自己的工作目录解析，因此官方右栏里天然只有这条会话的文件——"四个模型互不相干"来自会话作用域与目录隔离，而不是四份界面实例。
- run 结束时按目录读取一份产物清单写入 `runs[].artifacts`，作为运行结束时的记录；`refreshArtifacts` 可更新这份记录。没有会话标识或没有独立目录的旧任务，界面如实说明。
- **已知限制**：目录隔离解决写污染与归属，不解决读泄漏。DSH 内置沙箱只有 `read-only` / `workspace-write` / `danger-full-access` 三档，`workspace-write` 的定义是"写入限制在工作区内"，读取通常不受此限。

## 被否掉的路线

1. **把 shell 的页面标识切成对话页去借右栏**：导航高亮跳到「对话」、左栏变对话历史，场景归属丢失。已删除。
2. **在包页面里再造一份官方右栏**（启动期临时改上游源码导出 `RightbarSeat`，运行时新建 store/controller 并镜像槽位）：文档预览的渲染器挂在右栏 tab body 声明的子槽位下，镜像只能跳过；展开按钮又绑定官方 store。已删除。
3. **宿主自绘产物面板**（`renderArtifacts`：文件列表 + 文本/图片/HTML 预览）：不 patch 上游、能跑，但官方右栏加的任何能力它都没有，官方升级也追不上。已删除——保留它作为"产物面板"就等于放弃了本方案的第一原则。
4. **选择另一个空 `main` 面板**：会改变 `activePanelId`，导致官方右栏无在屏会话。当前方案仅替换 `main.conversation` 的内容，保留官方面板选择。
5. **持续认领 editor root**：已撤销。重复 composer 与程序 focus/导航联动存在反馈风险，改为只挂载一份 composer。

## 验收

- 开始测评后：表单下方出现 N 张模型卡片，每张卡片内是该模型真实的官方对话；可直接在卡片里继续对话。
- 点某张卡片后，官方右侧栏（产物/文件/终端/浏览器/改动评审/插件 tab）跟随该卡片；点卡片里的文件 chip 或产物卡片在官方预览里打开；切换卡片时右栏跟着切，离开那张卡片的状态仍由官方按会话保留，到达的那张按其规则收起。
- 右栏展开时点**另一张卡片**的产物：一次点击即可在该卡片自己的右栏里看到这个文件，面板不被收起、也不需要再点第二次（跨卡片首次点击曾经会先收起再放弃打开）。
- 嵌入头部条的「右侧栏 / 收起右栏」反映列里真实状态：当前卡片的面板展开时显示「收起右栏」，收起或当前显示的是别的卡片时显示「右侧栏」。
- 「← 对话」后 frame 回到用户原来的会话，中央列回到官方对话（进入前停在哪一列都不受影响）。
- 在任意一张卡片（包括点过、切过之后的那张）里输入：官方占位文字消失、发送键可用。每张卡片的 editor root 都是自己的输入框，frame 中央列没有重复输入框。
- 并发加载、超时后重试、加载中离开、重复进入详情及退出会话恢复均需验证。
- 对话模块、设置模块、其他能力包行为不变；退出测评页面后 frame 回到用户原来的会话。
