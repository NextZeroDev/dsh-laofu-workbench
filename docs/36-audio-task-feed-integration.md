# 配音任务与内容安排的统一查询

2026-09-23。内容安排生成的配音、字幕此前只写入项目 `media/runs.json`，当前配音页面却只查询根目录 `audio-tasks.json`，造成产物已经用于成片而配音页面没有记录。

## 修复契约

- `listAudioTasks` 汇总独立音频任务与项目配音任务，再统一执行账号筛选、搜索、状态统计及分页；不迁移、复制或重新生成历史媒体。
- 项目配音的稿件来自任务冻结快照，媒体来自该任务保存的不可变产物引用。字幕按来源音频文件关联，避免多次配音后把字幕挂到错误版本。
- 读取音频、任务详情、字幕重试与校对接口同时接受两类音频任务。历史项目配音可以查看和试听，修改与重试仅允许当前稿件的当前配音。
- 校对字幕按现有项目版本约束提交，保留原始 ASR 产物；新版本文件和校对记录归属原配音任务。改动字幕仍会使后续视频、质检和发布资料失效。
- 执行详情按保存的产物指针读取配音、字幕结果，不使用项目的最新产物替换历史。页面分别提供配音和字幕的执行入口。

## 其他模块检查

| 模块 | 安排与页面的共同数据来源 | 结论 |
|---|---|---|
| 信号 | 信号存储中的来源、批次及采集记录 | 无独立的安排结果库 |
| 选题 | `topic-generations.json` 与项目选题产物 | 无同类漏接 |
| 写稿 | `script-generations.json` 与项目稿件产物 | 无同类漏接 |
| 视频 | 项目 `media/runs.json`，按视频类型汇总 | 无同类漏接 |
| 发布 | 项目成片、QC、发布资料和 `publish-tasks.json` | 无同类漏接；只陈列通过 QC 的成片 |
| 内容安排 | `schedules.json` 的轮次与阶段引用 | 无同类漏接 |

发现并同时修复项目媒体执行详情没有展开产物文件引用的问题；否则字幕阶段虽成功，详情仍可能缺少 SRT。结果面板仅把包含发布文案的数据作为发布资料展示。

## 验证

- `npm test`：语法、Profile、能力包检查及 296 项测试通过，0 失败、0 跳过；最终调整后，前端和媒体主机语法、8 项客户端测试及 3 项媒体/执行详情定向回归再次通过。
- 新增回归覆盖项目配音进入列表、音频字节读取、字幕关联、原始 ASR 保留、字幕校对、失败重试、历史版本写入保护，以及混合任务列表的账号/搜索/状态/服务商筛选与分页。
- 执行详情测试覆盖不可变产物引用、产物读取、不回写历史记录及拒绝不匹配的产物。
- 实际本地数据的 3 轮安排逐项引用核对通过。音频查询返回 4 条：原独立任务 1 条，安排生成 3 条；视频和发布各 4 条。
- 使用只读验证服务加载真实 React 页面及本地已完成产物：4 个播放器能读取音频时长，定时字幕抽屉显示真实时间码，执行详情能显示字幕内容。没有调用真实 TTS/ASR 或修改生产产物；编辑与重试用隔离测试和模拟服务验证。
