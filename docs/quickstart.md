# 快速开始：从安装到第一条口播视频

本指南面向首次使用工作台的本机单用户。工作台可以持续接入独立场景能力包；下面以随仓库提供的第一个包“口播视频内容创作”为例。

## 1. 安装工作台

准备 Git、Node.js `^22.19.0 || >=24.0.0`、npm、Corepack 和本机 C/C++ 编译环境。建议使用 Node.js 22 LTS 最新补丁版本；macOS 编译工具可通过 `xcode-select --install` 安装。其他系统的完整安装和媒体制作兼容性需要在目标环境验证。

```bash
git clone https://github.com/ScarecrowFu/dsh-laofu-workbench.git
cd dsh-laofu-workbench
npm ci
npm run setup
npm run dev -- --port 4173
```

根目录依赖使用 npm 锁文件安装。`setup` 会克隆、检出并构建 [UPSTREAM.lock.json](../lwb/UPSTREAM.lock.json) 指定的 DSH，在上游目录使用其 pnpm 版本；不要在根目录另行初始化 pnpm 工作区。

上面启动的是 Web 端。要使用桌面开发端，在完成 `npm ci` 和 `npm run setup` 后，运行 `npm run dev:desktop` 代替 `npm run dev -- --port 4173`。切换 Web/桌面端前先退出另一 Host；两端共用本机业务数据，不支持并发写入。当前签名安装包尚未验收，更多信息见 [Desktop 与 Web](37-desktop-parity.md)。

Web 端应在浏览器打开老傅工作台，桌面端应打开工作台窗口，均显示“对话”“场景能力包”“设置”。首次启动没有预置业务账号、稿件或成片。Web 端若浏览器没有自动打开，用终端打印的完整带令牌 URL 访问；遇到错误先看[故障排查](troubleshooting.md)。

这是本机单用户工作台：Web 端是浏览器访问本机 Host，Desktop 端使用同一套 LWB 页面和能力包。LWB 账号不是启动前置条件。你可以不登录并使用自己的 DSH/百炼凭据，也可以登录 LWB 账号使用官方提供的模型和媒体服务；后者按 ATS 返回的积分和会员规则计费。

## 2. 选择 AI 模型

两种方式任选其一。场景任务默认跟随 DSH 默认模型，不会因为登录 LWB 自动切换：

- **LWB 账号**：在「设置」登录，确认账号和模型服务可用；到同页「场景任务默认模型」选择「指定场景任务模型」，在列表中选可用的 LWB 模型并保存。模型服务按账号的会员和积分规则提供，源码不附带免费额度。
- **自己的服务商凭据（BYOK）**：到「设置 → DSH 系统设置 → 打开设置 → 模型」添加服务商、API 凭据和模型，设为 DSH 默认模型；在「设置 → 场景任务默认模型」保持「跟随 DSH 默认模型」。也可以在那里单独指定已配置的模型。

在「对话」中选择一个普通工作区，发送简短请求验证所用模型的连接；对话模型与场景任务默认模型分别管理，临时切换对话模型不会自动改动场景任务设置。口播包的业务页面不需要新建普通对话或选择普通工作区，它会使用自己的专属工作区。账号定位完善、选题、写稿和视频 Agent 使用场景任务选定的模型。视频制作需要模型支持工具调用；独立审片还需要图片输入能力，不要仅凭列表中出现名称就认为服务可用。

## 3. 加载第一个场景能力包

打开「场景能力包」，找到「口播视频内容创作」，点击「加载」。左侧应出现账号定位、信号、选题等八个入口。

仓库内的包自动进入目录，不需要再运行 `pack:install`。外部包才需要先在本机注册源目录，再到页面加载。已启用的包会在下次启动时恢复，卸载只停止运行并移除菜单，保留业务文件与配置。

内置信号源默认启用，会按采集规则访问公开来源。可在“信号”的来源管理中停用不需要的来源；采集状态和错误可以在页面查看。

## 4. 配置媒体制作依赖

只测试选题和写稿，可以稍后再完成这一节。

### 本地工具

安装 FFmpeg，并确保启动工作台的终端能够执行：

```bash
ffmpeg -version
ffprobe -version
```

macOS 如已安装 Homebrew，可运行 `brew install ffmpeg`。其他系统请按 [FFmpeg 下载说明](https://ffmpeg.org/download.html)安装对应构建。

在项目根目录下载 Remotion 所需的渲染浏览器：

```bash
npx --no-install remotion browser ensure
```

也可以显式使用本机 Chrome/Chromium 的**可执行文件**。例如 macOS 的 Google Chrome：

```bash
export LWB_REMOTION_BROWSER_EXECUTABLE="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
npm run dev -- --port 4173
```

在已有进程启动后设置环境变量不会影响该进程，需要重启工作台。中文视频还需要本机可用的中文字体；出现方框或缺字时先检查字体环境。

### 服务连接

LWB 账号服务和用户自有服务是两条独立路径：

- **LWB 账号**：在「设置」登录，查看会员和积分；在场景包的服务配置中选择「LWB 账号」。调用由 ATS 服务端计费，源码不附带免费额度。
- **用户自有服务（BYOK）**：不需要登录 LWB，在 DSH 模型设置或场景包配置中填写自己的供应商凭据；额度、区域、模型权限和费用由对应供应商负责。

| 用途 | 配置入口 | 注意事项 |
|---|---|---|
| AI 创作与审片 | 设置 → 场景任务默认模型 | 指定 LWB/其他可用模型，或跟随已配置的 DSH 默认模型 |
| 配音和字幕识别 | 配音 / 字幕 → 连接配置 | 选择 LWB 账号或百炼；BYOK 时保存自己的媒体服务 API Key |
| 封面生图 | 发布 → 封面生图 | 选择 LWB 账号或百炼；它与媒体连接是不同的配置入口 |

同一个供应商的 Key 可能可用于多个入口，但配置不会自动互相覆盖。请确认对应模型权限、区域/工作空间及额度；这些请求可能产生供应商费用。LWB 账号的会员和积分购买在「设置」完成，服务是否可用以 ATS 目录和账户状态为准。

## 5. 完成第一条内容

1. **账号定位**：创建账号，填写受众、内容方向和表达要求；也可以使用“通用（无账号定位）”进行测试。
2. **信号**：检查采集结果。单个来源失败时，可以在选题时取消该渠道，使用其他可用来源。
3. **选题**：选择账号、参与渠道和可选的选题角度，点击生成并确认。任务会补采当天缺失的渠道；生成完成后推荐候选自动加入待写稿，其他候选可按需选择。
4. **写稿**：选择待写稿选题、篇幅和额外要求，点击「写稿」，核对确认框后启动。生成完成会保存稿件；需要调整时打开稿件编辑或润色，编辑后通过「保存并进入配音」提交。
5. **配音 / 字幕**：选择已保存稿件，核对内容、服务和音色。默认同时生成字幕，确认后开始任务。配音成功而字幕失败时，音频仍然保留，可单独重试字幕。
6. **视频 / 预览**：选择已完成配音的稿件，设置横竖屏、字幕、可选 BGM 和画面要求，确认后生成。DSH 创作 Agent 制作 Remotion 工程，主机渲染并执行技术质检、独立审片；查看执行详情定位失败阶段。
7. **发布**：检查通过质检的成片，打开发布资料，生成或修改标题、文案、标签及封面。预览、下载并自行发布到目标平台。

首次验证建议使用短篇稿件，先跑通一条完整流程。完成本节后，发布页应能查看通过质检的成片及其资料；只出现任务记录不代表制作成功。

配音页也支持直接输入文稿创建独立音频任务。要沿完整视频流程继续，请从已有项目稿件进入配音，确保音频与项目关联。

## 6. 再配置内容安排

手动流程跑通后，在「内容安排」中配置账号、执行日期/时刻、参与渠道、每轮条数和执行深度。

调度器运行在工作台服务进程中：关闭浏览器不会停止调度，退出服务则无法到点执行。错过的时刻不会自动补跑；执行记录以页面显示为准。深度到达成片或发布资料时，流程会自动推进稿件确认，请按需要选择停在写稿阶段。安排不会自动向视频平台发布。

## 7. 保存、备份与更新

默认所有产品状态都在 `lwb/local/`：账号、素材、稿件、音视频、运行记录、连接配置、凭据和原生会话。数据结构见[运行目录说明](31-runtime-data-layout.md)。

更新前停止服务并备份这个目录；自行指定过 `LWB_DSH_HOME` 或 `LWB_PACK_REGISTRY` 时，还应备份对应位置。源码更新后，在项目根目录执行 `npm ci`、`npm run setup`、`npm test`，确认依赖和上游版本匹配后再启动。不要在任务执行中更新运行时代码。

不要把包含凭据、会话内容或媒体素材的运行目录上传到 Issue 或公共仓库。卸载能力包、清空业务数据、删除包源登记分别有不同含义，操作前阅读[生命周期说明](12-capability-packs.md)。

## 当前版本的数据边界

当前锁定 DSH `dsh-v0.2.0-rc.2`。默认从全新 `lwb/local/current` 启动，不读取或迁移旧目录；旧文件保留。桌面启动方式见 [Desktop 与 Web](37-desktop-parity.md)，升级检查见 [扩展边界](38-dsh-extension-boundary.md)。
