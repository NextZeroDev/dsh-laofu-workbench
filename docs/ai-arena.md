# AI竞技台：首版设计与验收

本包源码位于 `lwb/packs/ai-arena/`，开发时自动发现；尚未加入桌面发行版随带清单，发行版归属由产品发布团队决定。

## 首版范围

- 首发 15×15 自由五子棋，黑方先手，无禁手，连续五颗及以上获胜。规则判定采用 MIT 许可的 `@algorithm.ts/gomoku@4.0.5`；本包只做坐标、占位、轮次和状态适配。
- 两名选手选择 DSH 已配置的模型路由，允许同模型自我对弈。推理强度在模型目录公开支持时可选择；底层真实模型未知的 LWB 档位保留档位身份，不推断具体模型。
- 每次决策创建独立的标准 DSH Agent Session，仅发送当前棋盘、规则与必要的纠错反馈，避免累积此前回合的思考上下文。单次回复被截断时在同一 Session 中继续；暂停恢复保留关联的会话和用量审计。比赛事件将双方各回合 Session 关联起来，官方对话窗口仅供回看，不提供可干扰比赛的输入框。
- 所有选手使用同一系统指令；对手发言不进入参赛请求。选手发言是模型输出的简短表达，不声称是完整内部推理；实际返回的 reasoning 仅保存在原始记录中。
- 非法坐标、占用落点、回复格式不合法均记为违规，默认重试一次，再次违规判负。服务错误或截断暂停比赛，由用户决定继续，不计为棋力失败。
- 暂停在当前回合结算后生效；取消立即停止调用，迟到回复不提交为落子。关闭浏览器不停止比赛；停止 Host 或卸载包中断比赛，重新加载后需要人工继续。
- 模型调用、每步输出、累计已报告 Token、单步时限和总落子均受配置约束。累计 Token 在回合边界检查，可能超出至多一轮实际用量；未报告用量明确显示不完整，不伪造费用。这里的调用次数是 DSH 逻辑调用，不保证供应商传输层没有重试。
- 输出预算按模型目录动态计算：两名选手共同取较小的 `maxOutputTokens`，当前 LWB 适配器的有效上限为 32768，低于该值的模型会进一步收窄竞技台输入上限。DeepSeek 官方模型目录的 V4.1 Flash 上限为 393216，但通过当前 LWB 路由时仍以 32768 为有效上限。每步默认 32768，累计预算默认 4000000、最大 20000000；`max_tokens` 同时覆盖思维过程和最终回答。
- 不再提供快速或深度模式切换。新比赛单步时限默认 300 秒，可设置 5—1800 秒；达到时限后暂停，不自动重试或判负，暂停页面可调整时限后继续。历史比赛保留原始请求与结果，恢复时自动将调用配置转为 `native` 并记录事件，后续使用正常调用。历史快棋恢复表单默认至少 300 秒，但提交前不改变已保存的时限。

## 数据与恢复

`<pack-workspace>/data/matches/<match-id>/match.json` 是每场比赛的事实源，包含配置、规则版本、模型身份、棋盘和事件；串行写入并通过原子替换提交。事件依次记录 request、response、move/invalid、error/interrupted、finished/cancelled。

原始回复先保存为 pending，再校验并提交动作。Host 在收到回复后中断，继续时可消费已保存的回复，不重复请求。请求已经发出但未收到回复时无法确认供应商是否完成或计费，不自动重新调用，先暂停等待用户决定。重启前请求仍计入调用次数。

恢复比赛前检查游戏规则版本；版本变化时保留记录并要求创建新比赛，避免按不同规则继续旧局。

完整 JSON 下载包括各回合实际输入、输出、用量、reasoning 和配置；Markdown 是便于阅读的战报。离线 HTML 嵌入确认动作和发言，不依赖网络、模型或其他包，支持跳步及播放。导出文本和 HTML 对模型文本作相应安全编码。

## 视频

视频通过现有 Remotion 技术栈渲染固定模板，棋盘与台词来自同一份比赛事件；每步默认 3 秒，额外保留终局画面。横屏为 1280×720，竖屏为 720×1280，H.264 MP4。第一版包含文字发言，无配音、BGM、自动解说或精华剪辑。

渲染需要 FFmpeg、ffprobe 和 Chrome。macOS 默认使用已安装的 Google Chrome，其他环境可设置 `LWB_REMOTION_BROWSER_EXECUTABLE`。成片用 ffprobe 检查尺寸和时长。下载通过有界分块 RPC，绑定导出版本；不沿用口播包的整文件 80 MiB 读取方式。

## 扩展边界

`games.mjs` 在竞技包内部管理游戏定义。每个游戏提供身份与版本、人数、create、observe、apply；宿主负责预算、错误、存储和回合调度。目前仅实现双人轮流行动，下一种同时行动或隐藏信息游戏必须扩展调度协议及选手视角，不是只修改提示词。浏览器和视频需为新游戏增加专属画面适配。

竞技台不暴露一次性模型 completion 绕过路径；模型调用统一受 DSH Session、能力包卸载信号、取消信号和权益边界管理。普通对话、口播 Agent、测评会话继续使用各自原有的 DSH 路径。

## 2026-10-03 决策速度优化（历史实施，快速策略已移除）

以下为当时的实施与验收记录，当前行为以首版范围及末尾“移除快速模式”为准。

### 原因与实施

实际日志表明等待主要发生在生成推理内容期间，而非棋盘渲染或落子动画。原 Qwen 第三次请求超时 300 秒，已返回约 48120 字符推理、没有最终答案；GLM 第三手耗时 177.4 秒、生成 14317 Token，第五手 159.2 秒、生成 15632 Token。提高输出上限解决截断，但不会主动控制思考量；仅延长超时无法提供合适的观赛节奏。

- 新比赛默认快棋，保留深度模式。每步 Token 默认仍为 32768，模型容量和累计预算不变；快棋默认 45 秒期限，深度默认 300 秒。时限是等待上限，不是生成速度保证。
- 百炼 Qwen 3.8 Flash/Max、DeepSeek V4.1 Flash：快棋单次请求发送 `enable_thinking:false`。GLM 5.3/Prime：发送 `enable_thinking:true, reasoning_effort:low`，不假设可以关闭 GLM 思考。其他供应商优先使用目录明确支持的 off/minimal/low；没有公开能力时只优化提示，模型选择器会显示“模型默认推理”。不通过相似名称猜测其他供应商的参数。
- 控制只针对选定百炼端点与模型，复用宿主管理凭据和配置快照，保留自定义请求头、传输及超时配置，不修改用户模型服务设置。普通模式、其他模型路由、对话和测评会话保持原调用路径。
- 百炼的上述单次控制使用公开 `PiAiAdapter`，因为当前 `LlmRuntime.prepareCall` 未提供任意单次供应商参数入口。这个明确选择的快棋分支不经过 `llm/stream` 中间件，但仍经过能力包权益、卸载信号、容量校验、供应商凭据和比赛审计。部署若依赖该中间件进行额外审计或限流，需先补齐对应保障，或使用深度模式的原运行时路径。不修改 vendor 文件或动态替换全局适配器。
- 快棋用完整落子列表替代重复的 ASCII 棋盘，保留全部棋子、身份、坐标和规则；要求检查立即获胜及必要防守后提交合理落点。选手发言仍由本次模型生成，与合法动作同时展示，不追加第二次模型请求，不生成代下动作。
- 回合间隔由 1200ms 缩短至 250ms。生成时显示等待响应、思考、生成落子与发言及实际耗时；这些实时元数据不逐块写盘，不展示内部推理文本。完整记录保留实际执行策略和首个内容到达时间，战报标明每手模式及策略。
- 旧比赛无 `pace` 时按深度继续。暂停后可显式切换模式与时限，变更记入事件；超时仍暂停，保留落子和已返回内容，不自动续局或判负。此次原 GLM 对局在当前回合超时后暂停，保留 12 手，未自动恢复。
